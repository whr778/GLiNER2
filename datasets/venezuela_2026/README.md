# Venezuela 2026 — real double-blind test for the EKF/MHT tracker

Paper 1's real-world capstone: run the pipeline (fine-tuned casualty extractor → EKF/gate
tracker) on the **real** 2026 Venezuela earthquake reporting stream and score its toll
estimate against the **official** figure trajectory. This is the model-mismatch test — the
extractor was fine-tuned on synthetic (sonnet-5) text; here it faces real news. See
[EKF_MHT_DESIGN.md](../../tools/events_working_papers/EKF_MHT_DESIGN.md) §12-13.

Event: magnitude 7.2 (near San Felipe) + 7.5 (near Yumare) earthquakes, 24 Jun 2026.

## ⚠ Copyright policy (strict)

Commit **only**: source URLs + timestamps (`sources.jsonl`), model-**extracted** observations
(`observations.jsonl`), and the official GT trajectory (`trajectory.jsonl`). **Never** commit
full article text. Article text is fetched at eval time into a **git-ignored** cache
(`data/venezuela_text_cache/`) and consumed by `ingest.py`; only the extracted figures persist.

## Layout

| file | role | committed |
|---|---|---|
| `sources.jsonl` | reporting stream: `{url, outlet, published, tier}` (no text) | yes |
| `observations.jsonl` | extracted obs: `{stream_id, t_hours, role, value, qualifier, source, url}` | yes (generated by `ingest.py`) |
| `trajectory.jsonl` | official GT toll over time (the answer key) | yes |
| `data/venezuela_text_cache/` | fetched article text, keyed by url hash | **no (gitignored)** |

`t_hours` origin = **2026-06-24 00:00 UTC** (mainshock day).

## V3 first-pass finding — synthetic→real transfer (4 sources)

The fine-tuned extractor (synthetic sonnet-5 training) on **real** Venezuela news:
- **dead / injured transfer holds.** Bound the correct figures amid heavy distractors —
  **188, 1,520/1,500, 164, 1,719, 5,034** — not the USGS 10,000 *forecast*, the 1812
  historical 30,000, 15,866 homeless, 30,000 workers, 2,700 experts, or magnitudes 7.2/7.5.
- **Two real-world failure modes** the synthetic data didn't cover:
  1. **Predictions.** A USGS "probability of exceeding 10,000" was mis-bound to `dead`/
     `missing` — a forecast, not a current toll. Needs a filter (or the tracker's innovation
     gate should reject the implausible-high spike).
  2. **`missing`.** Real articles state missing as "thousands"/"tens of thousands" with **no
     clean number**, so the model grabs a nearby figure (10,000, 164, 30,000). `missing` is
     unreliable on real news — as on synthetic, but here for a different reason (no figure to
     bind). Recommend: drop `missing` for the real eval, or add an "abstain when no number"
     behavior.
- **Implication:** dead/injured are trackable on real news; predictions + `missing` are the
  gaps. Confidence (0.9 cut) did *not* filter the mis-binds.

## V4 mini-run — track the dead toll (`track.py`)

Irregular-timestamp real-data tracking of `dead` vs the official GT (`evaluate.py` estimators
reused; they handle arbitrary grids).

- **The 10,000 prediction corrupts the tracker** — EKF **9,190** vs GT 188 at t=24h. The
  one-sided innovation gate does **not** defend it: it rejects implausibly-*low* readings (to
  admit real jumps), so a spuriously-*high* prediction sails through. (Corrects an earlier
  optimistic claim that the gate would reject it.)
- **A dynamics/rate filter fixes it** (`--max-rate`): drop an upward reading whose accrual
  rate from the last kept value is impossible (188→10,000 in ~0h ≫ any plausible rate;
  188→1,719 over 4 days is fine). Dead then tracks **188 → 1,719** correctly.
- **Residual gaps are coverage, not tracker:** t=48h shows 188 not the official 920 because
  the CNN report was HTTP-451 blocked; nothing past t=120h because collection stops there.
  → V3-full (more, non-CNN sources) is the lever, not more tracker tuning.
- **Candidate for the main tracker:** the rate filter is a general defense against high
  outliers on rising signals (the one-sided gate's blind spot) — consider folding into
  `evaluate.py`.
